Duet 1.1.0 lets an authorized orchestrator agent organize a workspace on your behalf — spawning agents and arranging the canvas — but only after you explicitly approve it.

## New
- **Orchestrator delegated canvas control.** A Lead/orchestrator agent can ask for permission to create and place agents, and create, move, resize, configure, connect or remove canvas items. Nothing happens until you approve it: a dialog names exactly what's being requested ("Create and start coding agents", "Move canvas items", …), and deleting items always needs its own separate approval — never implied by the rest. The grant is scoped to that one agent in that one workspace, and is never saved to disk: it's gone the moment you revoke it, that agent stops, or Duet closes.
- **`duetctl canvas` commands.** `list`/`inspect` (read the canvas as structured data — ids, kinds, positions, sizes), `create`, `move`, `resize`, `configure`, `connect`, `remove`, and `find-space` (ask for an unused spot before placing something new).
- **`duetctl control` commands.** `request` asks for capabilities with a reason; `status` reports what's currently granted.
- **Placing and tasking a spawned agent.** `duetctl agents create` now takes `--x`/`--y`/`--width`/`--height` to position the new card, and `--task` to give it something to start on immediately.
- **A visible, revocable grant.** Once an agent holds canvas control, its card's menu shows "Revoke canvas control" — click it and the authority is gone immediately, no restart needed.

## Fixed
- A removed Portal node's browser view is now actually torn down instead of continuing to run invisibly in the background.
- Deleting a canvas item through the new orchestrator path, then undoing it, now restores its connections too, not just the item itself.

## Install
Requires GTK4, libadwaita, VTE (GTK4), GtkSourceView 5 and WebKitGTK 6.0, plus `git`. On Arch:

```sh
sudo pacman -S gtk4 libadwaita vte4 gtksourceview5 webkitgtk-6.0 git
tar xzf duet-v1.1.0-x86_64-linux.tar.gz
cd duet-v1.1.0-x86_64-linux && ./install.sh
```

Upgrading from 1.0.x needs no migration: your workspaces load as they are. Delegated-control grants are runtime-only and were never part of what gets saved, so there's nothing to migrate there either.
